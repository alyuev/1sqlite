1. ПАТЧИ ДВИЖКА SQLite (SQL_DBF\SQLite\sqlite3.c)
------------------------------------------------------------------
Регистронезависимость кириллицы (таблица oasUpper2Lower[0xFFFF],
строится в utex.cpp через CharLowerBuffW; заменяет sqlite3UpperToLower
в местах фолдинга регистра):
  - макросы sqlite3Tolower, UpperToLower, charMap -> oasUpper2Lower
  - хеш ключевых слов; SQLITE_FUNC_HASH (хеш имён функций); strHash
  - sqlite3_stricmp / sqlite3StrICmp / sqlite3_strnicmp — переписаны
    на сравнение по КОДОВЫМ ТОЧКАМ (sqlite3Utf8Read + oasUpper2Lower),
    а не по байтам -> корректное сравнение и коллация NOCASE/_1C.
  - sqlite3StrIHash — хеш ИДЕНТИФИКАТОРОВ по кодовым точкам.
    [ФИКС из авторского 3.46] Без него имена полей в разном регистре
    (GROUP BY мАрКа, алиасы) давали "no such column".
  - patternCompare (LIKE/GLOB) — регистронезависимый разбор кириллицы,
    в т.ч. в поиске после % (инфикс).

upper() / lower() — через Win32 CharUpperW / CharLowerW (полный Unicode,
работа на UTF-16; кириллица меняет регистр корректно).

Даты 1С:
  - поле char date1C в struct DateTime;
  - isDate() — 8-значная строка "ГГГГММДД" (только цифры) распознаётся
    как дата 1С (раскрывается в ГГГГ-ММ-ДД, флаг date1C);
  - dateFunc() — компактный вывод "ГГГГММДД" при date1C
    (date('20240101')='20240101', обычные даты не меняются);
  - case 'F' в форматтере strftime — тоже компактный вывод при date1C;
  - case 'q' — квартал (1..4).

connect1CTable — авто-подключение DBF-таблиц 1С по имени в запросе
  (хук в sqlite3LocateTable; сама функция в database.cpp).

LIKE по индексу с кириллицей — в isLikeOrGlob отключена оптимизация
  LIKE->диапазон для НЕ-ASCII префикса (байтовые границы ненадёжны для
  многобайтной кириллицы под 1251). Полный LIKE через patternCompare
  всегда корректен. Для скорости поиска по подстроке — FTS5 trigram.
  (Решение автора из 3.42.0.30.)

3. ИЗМЕНЕНИЯ КОМПОНЕНТА (SQL_DBF\database.cpp)
------------------------------------------------------------------
  - Регистрация SQL-функций to_base64 / from_base64.
  - БЕЗОПАСНЫЙ фикс пустой даты (typization ttDate + дефолт):
    пустая дата -> ПустоеЗначение()=1. Делается через локальный
    CDate (CDate d; d.m_DateNum=0; *pValue=d), БЕЗ прямой записи в
    pValue->m_Date по "зашитому" смещению (та прямая запись роняла
    1С на реальной базе — раскладка CValue в нашей версии 1С иная).
  - УложитьТЗ: строковые колонки с длиной типизируются как varchar(N)
    (sqlite odbc корректно работает со строками длиннее 255).
  - open(): при ошибке открытия всегда бросается 1С-исключение.
  - typeField (типизация колонки по заголовку): маркер типа ':'/'$' ищется
    только ВНЕ строковых литералов '...'. Иначе у БЕЗЫМЯННОЙ колонки SQLite
    подставлял заголовком весь текст выражения, и ':'/'$' внутри него
    принимались за тип 1С -> "Неправильная типизация в колонке". Касалось JSON
    (json_extract(x,'$.путь'), объект '{"a":42}') и масок времени ('%H:%M:%S').
